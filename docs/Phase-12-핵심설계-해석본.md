### 1) 왜 "정예 2종 엔진(DeepFilterNet / Speex DSP)" 구조로 최적화했을까요?
* **실제 청음 품질 검증 기반 정예화**: 
  - `RNNoise`의 주파수 분할 순환 연산에서 발생하던 매미 날개짓 아티팩트(Flapping noise)를 사용자 피드백을 통해 식별하고 완전 제거.
* **검증된 정예 2대 엔진 라인업**:
  1. **`DeepFilterNet (스튜디오 권장)`**: 32-ERB 고해상도 대역 + 딥 레지듀얼 에르미트 필터로 사람 목소리 왜곡 0% 유지 및 키보드/클릭/환경 잡음 실시간 -30dB 억제.
  2. **`Speex DSP (초절전)`**: 16-Critical Band 기반 고속 Speex 공식 서브트랙션으로 선풍기/에어컨/팬 소음 전용 초저부하 컷오프.

### 2) 왜 클라우드 서버 API가 아닌 "브라우저 온디바이스(로컬 WASM)" 방식이어야 할까요?
* **초저지연 (5~10ms)**: 내 컴퓨터/스마트폰 CPU 안에서 즉시 지워버리므로 통화 지연 체감이 전혀 없습니다.
* **서버 비용 0원 & 완벽한 사생활 보호**: 중앙 서버 GPU 비용이 들지 않고, 음성이 외부로 유출되지 않습니다.

### 3) 왜 `AudioWorklet` 기술이 필수적일까요?
* 자바스크립트 메인 UI 스레드와 완전히 분리된 백그라운드 오디오 전용 스레드에서 WASM 신경망을 구동하여, 화면 스크롤이나 버튼 클릭 시에도 음성이 1ms도 끊기지 않습니다.

### 4) 노래를 부르거나 악기를 연주할 때는 어떻게 하나요? (무단절 바이패스 & 핫스왑)
* 마이크 설정 팝오버(`VoiceBar`)에서 AI 잡음 제거 토글을 끄면, AI 연산 노드를 우회하는 **무단절 바이패스(Bypass)** 경로로 즉시 전환되어 CPU 연산을 0%로 줄이고 원음 그대로의 풍부한 음역대를 전송합니다.
* **Destination 노드 불변**: 핫스왑이나 토글 시 `MediaStreamDestination` 노드를 재생성하지 않고 유지하여 WebRTC 송신 트랙(`replaceTrack`)이 끊기지 않습니다.
* **5ms 크로스페이드**: 모델 교체 시 5ms 선형 게인 보간으로 틱/팝 노이즈를 완벽 방어합니다.
* **Graceful Fallback**: WASM 로딩 실패 시 통화가 중단되지 않고 자동으로 바이패스(일반 마이크) 모드로 전환됩니다.

## 2. Phase 12 핵심 기술 용어 사전

| 용어 | 쉬운 설명 | Talklite에서의 역할 및 구현 상세 |
| :--- | :--- | :--- |
| **플러그형 엔진 (Pluggable Engine)** | 필요에 따라 부품처럼 갈아 끼울 수 있는 모듈식 구조 | RNNoise, DeepFilterNet, Speex 3종 모델을 끊김 없이 교체(핫스왑) 가능하도록 함. |
| **무단절 핫스왑 (Seamless Hot-Swap)** | 통화 중단이나 소리 튐 없이 부품(AI 엔진)을 실시간 교체하는 기술 | `denoiseSeq` 시퀀스 번호 가드와 5ms 크로스페이드로 팝 노이즈 없이 모델을 실시간 전환함. |
| **온디맨드 동적 로딩 (Lazy Loading)** | 필요한 순간에만 네트워크에서 파일을 다운로드하는 방식 | 사용자가 선택한 모델의 WASM 파일만 내려받아 초기 번들 크기와 페이지 로딩 속도를 최적화함. |
| **안전 폴백 (Graceful Fallback)** | 오류가 발생해도 서비스 전체가 죽지 않고 기본 기능으로 버티는 설계 | WASM 다운로드 실패 시에도 통화가 끊기지 않고 일반 마이크 모드로 안전하게 유지됨. |
| **온디바이스 AI (On-Device AI)** | 클라우드 서버 대신 사용자 기기 내부에서 직접 구동되는 AI | 네트워크 지연(0ms)과 서버 비용 없이 내 컴퓨터 안에서 실시간으로 잡음을 제거함. |
| **오디오 워클릿 (AudioWorklet)** | UI 화면과 분리된 독립된 백그라운드 오디오 전용 스레드 | 웹 화면이 멈추거나 렌더링이 일어나도 음성 데이터가 끊기지 않도록 보장함. |

## 1. 이슈별 상세 정리

### 1️⃣ [문제 1] 통화 참여 중 내 마이크 소리가 상대방에게 전혀 안 들림 (초기 시도)
* **발견된 문제**: 통화에 참여했는데 상대방에게 내 목소리가 전혀 전달되지 않음.
* **추측한 원인**: 새로 추가한 잡음제거 게인 노드가 0으로 잠겨있거나, 브라우저 자동재생 정책으로 `AudioContext`가 멈춰있다고 생각함.
* **해결 시도**:
  - `voiceAudioEngine.ts`의 `initializeInput` 노드 연결을 정리하고, `joinVoice` 시 `resume()`을 자동 호출하도록 수정.
* **결과**: ❌ **실패 (여전히 상대방에게 소리가 안 들림)** $\rightarrow$ 원인이 송신단 게인이 아니었음을 확인.

---

### 2️⃣ [문제 2] 통화 중 마이크 선택 드롭다운을 바꿔도 반영이 안 됨
* **발견된 문제**: 마이크 설정 드롭다운에서 다른 마이크를 골라도 즉시 기본값으로 풀려버림.
* **원인**: `VoiceBar.tsx`에 `value=""`가 고정되어 있었고, 선택한 마이크 ID를 기억하는 상태가 없었음.
* **해결 시도**:
  - `voiceStore.ts`에 `selectedAudioDeviceId` 상태를 추가하고 `localStorage`에 저장.
  - 마이크 요청 실패 시 `exact` $\rightarrow$ `ideal` $\rightarrow$ `기본 마이크`로 자동 전환하는 3단계 폴백 적용.
* **결과**: ✅ **성공 (선택한 마이크가 유지되고 장치 전환 정상 작동)**

---

### 3️⃣ [문제 3] 마이크 소리가 상대방에게 여전히 안 들림 (진짜 원인 규명 및 해결)
* **발견된 문제**: 1번 조치 후에도 상대방에게 목소리가 전혀 전달되지 않음.
* **진짜 원인 (2가지)**:
  1. **P2P 연결 수립 실패**: 네트워크 패킷 순서상 SDP보다 ICE Candidate가 먼저 와서 에러가 나고 버려짐 $\rightarrow$ P2P 연결 자체가 안 맺어짐.
  2. **Chrome 브라우저 버그**: Chrome은 `<audio>` 태그로 직접 재생하지 않으면 Web Audio로 넘어온 원격 스트림을 디코딩하지 않고 무음(0) 처리함.
* **해결 시도**:
  1. `webrtc.ts`에 `pendingCandidates` 대기 큐를 만들어 SDP 협상 전 도착한 후보를 보관했다가 협상 완료 후 일괄 연결.
  2. `voiceAudioEngine.ts`에 백그라운드 `<audio autoplay>` 태그를 추가하여 Chrome 디코더를 강제 기동.
* **결과**: ✅ **성공! (상대방에게 목소리가 정상적으로 들리기 시작함)**

---

### 4️⃣ [문제 4] 소리는 들리는데 상대방 말이 로봇 목소리처럼 변조되어 들림
* **발견된 문제**: 소리는 전달되는데 목소리가 기계/로봇처럼 심하게 울리고 변조됨.
* **원인**: 3번에서 추가한 `<audio>` 태그와 기존 Web Audio API가 **둘 다 스피커로 소리를 동시에 내보내면서 빗살 필터(Comb Filter) 위상 간섭**이 발생함.
* **해결 시도**:
  - `<audio>` 태그는 `muted = true, volume = 0`으로 설정해 Chrome 디코더만 깨우고 소리는 안 나게 막음.
  - 실제 스피커 소리는 Web Audio 단 1곳에서만 출력되도록 일원화.
* **결과**: ✅ **성공! (로봇 변조음 완전히 사라지고 깨끗한 원음으로 정상 통화 가능)**

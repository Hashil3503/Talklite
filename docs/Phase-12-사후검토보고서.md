### 🎙️ [문제 1] 통화 참여 중 내 목소리가 상대방에게 전혀 안 들리는 문제

#### ❌ [1차 시도] 송신단 게인 노드 및 AudioContext 수정
* **가설**: 새로 추가한 AI 잡음제거 게인 노드가 0으로 잠겨있거나, 브라우저 정책으로 `AudioContext`가 `suspended` 상태여서 마이크 소리가 안 나간다고 판단.
* **조치**:
  - `voiceAudioEngine.ts`의 `initializeInput`에서 노드 직결 충돌을 제거.
  - `joinVoice` 진입 시 `await eng.resume()`을 선행 호출하여 `AudioContext`를 활성화.
* **결과**: ❌ **실패 (여전히 상대방에게 소리가 전혀 안 들림)**
  - *실패 원인*: 마이크 볼륨(송신단)의 문제가 아니라, P2P 연결 자체가 안 맺어지고 있었음.

#### ❌ [2차 시도] 오디오 송신 파이프라인 1:1 직결 스왑 단순화
* **가설**: `denoiseBypassGain`, `denoiseInputGain` 등 복잡한 삼각 이중 게인 체인이 얽혀 신호가 유실된다고 판단.
* **조치**:
  - 복잡한 이중 게인 체인을 전부 걷어내고, OFF 시 `source → inputGain`, ON 시 `source → worklet → inputGain` 1:1 직결 스왑으로 단순화.
* **결과**: ❌ **실패 (여전히 상대방에게 소리가 전혀 안 들림)**
  - *실패 원인*: 송신단 구조는 깔끔해졌으나, 네트워크 P2P 수립 실패와 브라우저 수신단 버그는 그대로였음.

#### ✅ [3차 시도] P2P ICE Candidate 큐잉 및 Chromium 수신 디코더 강제 기동 (최종 해결)
* **진짜 원인 발견 (2가지)**:
  1. **P2P 연결 수립 실패**: 네트워크 패킷 순서상 SDP보다 ICE Candidate가 먼저 들어오면 브라우저가 버려버림 $\rightarrow$ **두 사람 간 P2P 연결 자체가 안 맺어짐**.
  2. **Chromium 브라우저 버그**: Chrome은 `<audio>` 태그로 직접 재생하지 않고 Web Audio로만 연결하면 **오디오 패킷 디코딩을 스킵(무음 처리)**함.
* **조치**:
  1. `webrtc.ts`에 `pendingCandidates` 대기 큐를 구현하여, SDP 협상 전에 도착한 Candidate를 보관했다가 협상 완료 직후 일괄 연결.
  2. `voiceAudioEngine.ts`에 백그라운드 숨김 `<audio autoplay>` 태그를 추가하여 Chrome 오디오 디코더를 강제 활성화.
* **결과**: ✅ **성공! (상대방에게 목소리가 정상적으로 들리기 시작함)**

### 🎛️ [문제 2] 통화 중 마이크 선택 드롭다운을 바꿔도 반영이 안 되는 문제

#### ✅ [1차 시도] 마이크 선택 상태 영속화 및 3단계 안전 폴백
* **원인**:
  - `VoiceBar.tsx`에 `value=""`가 하드코딩되어 마이크를 바꿔도 즉시 빈 값으로 리셋됨.
  - `voiceStore.ts`에 선택된 마이크 ID를 기억하는 상태가 없었음.
* **조치**:
  - `voiceStore.ts`에 `selectedAudioDeviceId` 상태를 추가하고 `localStorage` (`talklite_audio_device_id`)에 영구 저장.
  - `VoiceBar.tsx`의 `<select>`에 `value={selectedAudioDeviceId ?? ""}` Controlled 바인딩 적용.
  - 마이크 획득 실패 시 `exact` $\rightarrow$ `ideal` $\rightarrow$ `기본 마이크(audio:true)` 3단계 안전 폴백 적용.
* **결과**: ✅ **성공 (선택한 마이크가 드롭다운에 유지되고 장치 핫스왑 정상 작동)**

### 🤖 [문제 3] 소리는 들리는데 상대방 말이 로봇 목소리처럼 변조되는 문제

#### ✅ [1차 시도] 이중 출력 Comb Filter 해소 (스피커 가청 출력 단일화)
* **원인**:
  - 문제 1의 3차 시도에서 디코더용으로 추가한 `<audio>` 태그와 기존 Web Audio API가 **둘 다 스피커로 소리를 동시에 내보냄**.
  - 동일한 소리가 수십 밀리초 시차를 두고 스피커에서 합성되면서 **빗살 필터(Comb Filter / Flanger) 위상 간섭**이 발생해 로봇 목소리로 변조됨.
* **조치**:
  - `<audio>` 태그를 **`muted = true, volume = 0` (완전 무음)**으로 설정하여 Chrome 디코더만 깨우고 소리는 안 나게 차단.
  - 실제 스피커 소리는 **Web Audio API (`masterGain → ctx.destination`) 단 1곳에서만 출력**되도록 일원화.
* **결과**: ✅ **성공! (로봇 변조음이 완전히 사라지고 원음 그대로 깨끗하게 정상 통화 가능)**

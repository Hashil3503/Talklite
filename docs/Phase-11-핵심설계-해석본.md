## 1. Phase 11 핵심 아키텍처 해석

### 1) 왜 게임 도중에 방 정보를 실시간으로 수정할 수 있어야 할까요?
* **배경**: 4인 파티로 시작했다가 친구 1명이 더 와서 5인으로 늘려야 하거나, 랭크전을 끝내고 일반전을 하려고 해시태그를 `#골드`에서 `#즐겜`으로 바꾸고 싶을 때가 있습니다.
* **기존 문제**: 방 정보가 불변이면 방을 완전히 폭파하고 파티원들이 새 방으로 다시 모여야 했습니다.
* **해결책**: 방장이 방 안에서 **[⚙️ 방 설정 수정]** 버튼을 눌러 방 제목, 게임명, 해시태그, 최대 정원을 즉시 수정하면, 방에 있는 유저들과 로비 검색 결과에 실시간으로 반영됩니다.

### 2) 현재 4명이 있는데 정원을 3인으로 줄이려고 하면 어떻게 되나요? (정원 충돌 방어)
* **문제**: 현재 방에 4명이 이미 들어와 있는데 방장이 정원을 3명으로 줄여버리면 1명이 붕 떠버리는 시스템 모순이 발생합니다.
* **해결책**: 백엔드가 `newCapacity >= currentMemberCount`를 철저히 검증하여, 현재 방에 있는 인원수보다 작은 정원으로 줄이려는 요청은 **`409 Conflict (정원 충돌 에러)`로 즉시 차단**하고 방장에게 안내합니다.

### 3) 태그를 바꾸면 검색 결과는 어떻게 즉시 바뀌나요? (Lua 원자적 재색인)
* **원리**: Redis의 `update_room.lua` 스크립트가 실행되어, 이전 태그 목록(`tag:옛날태그:rooms`)에서는 이 방을 1밀리초 만에 지우고, 새 태그 목록(`tag:새태그:rooms`)에 즉시 등록합니다.
* **효과**: 로비에서 새로고침을 누르지 않아도 방 정보 변경 이벤트(`ROOM_UPDATED`)를 수신하여 방 카드가 즉시 바뀌며, 새 태그로 검색할 때 바로 노출됩니다.

## 2. Phase 11 핵심 용어 사전

| 용어 | 쉬운 설명 | Talklite에서의 역할 |
| :--- | :--- | :--- |
| **방 정보 실시간 수정 (Dynamic Room Update)** | 방을 폭파하지 않고 제목, 태그, 정원을 실시간으로 변경하는 기능 | 게임 모드 변경이나 파티원 증원에 맞춰 방의 속성을 유연하게 조정함. |
| **PATCH /api/rooms/{id}** | 방의 특정 속성들만 골라서 부분 수정하는 REST API 엔드포인트 | 방장 권한을 검증하고 변경된 메타데이터를 Redis와 MariaDB에 반영함. |
| **정원 충돌 방어 (Capacity Conflict Guard)** | 현재 체류 중인 인원보다 작은 정원으로 축소하려는 시도를 막는 규칙 | 파티원이 방에 남아있는데 정원이 초과되어 발생하는 오류를 원천 차단함. |
| **태그 원자적 재색인 (Atomic Tag Re-indexing)** | 이전 태그 삭제와 새 태그 등록을 한 번의 찰나에 끝내는 Redis 기술 | 검색 인덱스가 꼬이지 않고 로비 검색 결과가 마이크로초 단위로 즉각 반영됨. |
| **ROOM_UPDATED** | 방 정보가 수정되었음을 방 참여자와 로비 유저들에게 알리는 실시간 이벤트 | 참여자 화면 상단 헤더와 로비의 방 카드가 새로고침 없이 즉시 갱신됨. |

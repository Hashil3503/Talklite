## 1. Phase 7 핵심 아키텍처 해석

### 1) 왜 방장 전용 방 삭제(방 폭파) 기능이 필요할까요?
* **배경**: 기존 Phase 0~6 스펙에서는 영구 방(`PERMANENT`)이 사람이 아무도 없어도 MariaDB에 영구 보존되도록 설계되어 있었습니다. 하지만 방을 만든 방장이 클랜을 해체하거나 더 이상 방을 운영하고 싶지 않을 때 **방을 직접 삭제할 방법이 없었습니다.**
* **해결책**: 방장(`👑`)에게만 권한이 부여된 명시적 **[방 삭제하기]** 버튼과 API(`DELETE /api/rooms/{id}`)를 제공하여, 원하는 시점에 방을 완전히 없앨 수 있도록 합니다.

### 2) 방 삭제 버튼을 누르면 내부에서는 어떤 일이 일어나나요? (동기 일괄 삭제 체인)
방장이 방 삭제를 확정하면 시스템은 4단계 작업을 순차적으로 완벽히 처리합니다:
1. **권한 검증**: 요청자가 실제 해당 방의 `host`인지 확인 (일반 멤버가 삭제를 시도하면 `403 Forbidden` 차단).
2. **MariaDB 영구 삭제**: 영구 방인 경우 DB의 `permanent_room` 및 `permanent_room_chat` 테이블에서 해당 `room_id` 행을 즉시 일괄 삭제하여, 서버를 껐다 켜도 방이 다시 살아나거나 대화 찌꺼기가 남지 않게 만듭니다. (`RoomService.java:170~171`)
3. **Redis 인메모리 완전 파기**: `destroy.lua`를 실행하여 방 정보(meta), 멤버 목록, 음성 세션, 초대코드, 게임명/태그 검색 역색인(`game:`, `tag:`), 임시 밴 키 및 `room:{id}:messages` 채팅 캐시를 찌꺼기 없이 100% 삭제합니다. (`gc.lua`는 휘발성 방 마지막 퇴장 전용 — `SCARD==0` 가드로 동시 입장 시 파기 취소 / `destroy.lua`는 방장 폭파 전용 — 멤버 수 무관 강제 일괄 삭제)
4. **실시간 웹소켓 이벤트 전파**:
   * **방 안의 유저들 (`/topic/room/{id}`)**: `ROOM_DESTROYED` 이벤트를 받아 통화/채팅 세션이 종료되고 안내 메시지와 함께 로비로 자동 이동됩니다.
   * **로비의 유저들 (`/topic/lobby`)**: `ROOM_REMOVED` 이벤트를 받아 로비 목록에서 해당 방 카드가 새로고침 없이 즉시 사라집니다.

### 3) 다른 사람이 방 안에 머무르고 있을 때 방장이 삭제하면 어떻게 되나요? (강제 퇴장 처리)
* 다른 멤버가 채팅 중이거나 음성 통화 중이더라도, 방장이 방을 폭파하면 즉시 연결된 WebRTC 음성 및 STOMP 채팅이 안전하게 종료됩니다.
* 일반 참여자들의 화면에는 **"방장에 의해 방이 삭제되었습니다. 로비로 이동합니다."** 알림이 표시되고 로비 화면으로 리다이렉트되어 고아 유저로 남는 문제를 방지합니다.

### 4) 브라우저를 닫았다가 다시 열어도 방장 권한이 유지되는 원리는 무엇인가요? (localStorage 영구 보존)
* **배경**: 브라우저 탭을 닫거나 새로 열 때마다 유저 ID가 바뀌면, 자신이 만든 영구 방의 방장 권한을 잃어버리게 됩니다.
* **해결책**: 유저의 고유 식별자(`talklite_uid`)를 브라우저 영구 저장소(`localStorage`)에 보관하여, 브라우저를 껐다 켜거나 PC를 재부팅해도 **항상 '나'라는 유저 ID와 방장 권한이 영구 고정**되도록 합니다. 24시간 후 토큰이 만료되어도 기존 유저 ID로 새 토큰을 갱신하므로 방장 권한이 영구 보존됩니다.

### 5) 영구 방의 대화 내역은 어떻게 보존되고 복원되나요? (MariaDB & Redis 2중 저장)
* **배경**: 일반 휘발성 방은 대화 내역이 실시간 중계(Relay-Only)되어 브라우저를 닫으면 사라지지만, 영구 방은 클랜/고정 파티 공간이므로 **나중에 다시 들어왔을 때 이전 대화 맥락을 확인할 수 있어야 합니다.**
* **동작 원리** (`ChatService.java:65`):
  1. **실시간 캐싱 (Redis List — 모든 방)**: 모든 방에서 채팅 발생 시 Redis `room:{id}:messages`에 `LPUSH` + `LTRIM 0 99`로 최근 100건을 고속 캐싱합니다. (휘발성 방도 입장 직후 초고속 복원 가능)
  2. **영구 저장 (MariaDB — 영구 방만)**: 영구 방(`PERMANENT`)인 경우에만 `PermanentRoomChatRepository.save()`로 MariaDB `permanent_room_chat`에 영구 커밋되어, 서버 재부팅 후에도 대화가 유지됩니다.
  3. **자동 복원**: 방에 새로 입장하거나 새로고침한 사용자는 `GET /api/rooms/{id}/messages`를 통해 최근 대화(최대 50~100건)를 자동으로 불러와 채팅창에 보여줍니다.
  4. **방 폭파 시 완전 소멸**: 방장이 방을 삭제하면 MariaDB의 대화 기록도 깔끔하게 일괄 삭제됩니다.

## 2. Phase 7 핵심 용어 사전

| 용어 | 쉬운 설명 | Talklite에서의 역할 |
| :--- | :--- | :--- |
| **명시적 방 삭제 (Explicit Room Deletion)** | 사용자가 버튼을 눌러 직접 방을 소멸시키는 능동적 작업 | 방장이 영구 방/휘발성 방을 원할 때 즉시 DB와 메모리에서 완전히 파기함. |
| **방 폭파 (Room Destruction)** | 방이 삭제되면서 방 안의 모든 참여자를 강제 퇴장시키는 과정 | 삭제 시점에 방에 머물던 유저들의 세션을 일괄 정리하고 로비로 안전하게 이동시킴. |
| **ROOM_DESTROYED** | 방이 폭파되었음을 방 안의 참여자들에게 알리는 실시간 이벤트 | 참여자 브라우저가 이 이벤트를 감지하면 음성 트랙을 끊고 로비 화면으로 자동 전환함. |
| **403 UnauthorizedHostException** | 방장 권한이 없는 일반 사용자가 방 삭제나 강퇴를 시도할 때 거부하는 보안 에러 | 방 소유자 이외의 비인가자가 타인의 방을 무단 삭제하는 것을 방지함. |
| **동기 삭제 (Synchronous Deletion)** | Redis와 MariaDB를 지연 없이 즉시 한 번에 삭제하는 방식 | DB에는 남아있고 Redis에는 지워지거나, 그 반대로 남는 데이터 불일치를 원천 차단함. |
| **localStorage 영구 보존 모드** | 브라우저 하드디스크에 유저 ID를 영구 저장하여 보관하는 방식 | 브라우저 창을 닫거나 재부팅해도 내가 만든 영구 방의 방장 권한을 영구 유지함. |
| **permanent_room_chat** | 영구 방의 텍스트 대화 내역을 저장하는 MariaDB 테이블 | 휘발성 방과 달리 영구 방의 대화 내역을 영구 보존하여 재접속 시에도 과거 대화를 복원함. |
| **room:{id}:messages** | 최근 발생한 채팅 100건을 인메모리에 보관하는 Redis List 키 | 방 입장 시 MariaDB를 매번 조회하지 않고 초고속으로 최근 대화를 불러오는 캐시 계층. |
| **T-10** | 방 삭제 기능의 권한 차단, DB/Redis 소멸, 실시간 퇴장을 검증하는 자동화 테스트 | Phase 7에서 신설된 방 폭파 통합 테스트 시나리오. |
| **T-11** | 영구 방 대화 저장, 과거순 조회 복원, Redis 캐시 미스 MariaDB 폴백, 방 삭제 시 일괄 소멸을 검증하는 자동화 테스트 | Phase 7에서 신설된 영구 방 대화 영속화 통합 테스트 시나리오. |
